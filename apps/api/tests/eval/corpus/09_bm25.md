# BM25 Ranking Function

BM25, short for "Best Matching 25", is a probabilistic ranking function used by search engines to estimate the relevance of documents to a given query. It emerged from the Okapi information retrieval system developed at London's City University in the 1980s and 1990s, and it remains one of the strongest lexical baselines in modern retrieval. Despite the rise of dense neural retrievers, BM25 continues to appear as the first-stage candidate generator in countless production systems because it is fast, robust, and requires no training.

## From Term Weighting to a Scoring Function

At its core, BM25 assigns a score to each document based on the query terms it contains. The intuition builds on two classical observations. First, a document that mentions a query term many times is probably more relevant than one that mentions it once. Second, a term that appears in very few documents across the collection is more informative than a term that appears everywhere. BM25 combines these two ideas but refines them so that neither factor grows without bound.

The score of a document `D` for a query `Q` containing terms `q_1, ..., q_n` is a sum of per-term contributions:

```
score(D, Q) = sum over q_i of  IDF(q_i) * ( f(q_i, D) * (k1 + 1) )
                                / ( f(q_i, D) + k1 * (1 - b + b * |D| / avgdl) )
```

Here `f(q_i, D)` is the raw count of term `q_i` in document `D`, `|D|` is the document length in words, and `avgdl` is the average document length across the whole collection. The two free parameters `k1` and `b` govern the shape of the ranking, and tuning them is the main lever a practitioner has when adapting BM25 to a new corpus.

## Term Frequency Saturation

A defining feature of BM25 is that the contribution of a term rises with its raw count but levels off rather than growing linearly. This behaviour is called term frequency saturation, and it is controlled by the parameter k1. When a word already appears ten times in a passage, the eleventh occurrence adds very little evidence of relevance, so the formula deliberately dampens the reward for repeated matches.

Mathematically, the fraction `f * (k1 + 1) / (f + k1)` approaches an asymptote of `k1 + 1` as the frequency `f` grows large. A small k1 makes the curve saturate quickly, so that documents are ranked mostly on whether a term is present rather than how often. A large k1 keeps the response closer to linear, letting raw counts matter more. Typical values fall between 1.2 and 2.0, with 1.2 being a common default. The presence of this saturation term is the single biggest reason BM25 outperforms naive term-frequency weighting, which lets a spammy repeated keyword dominate the ranking.

## Document Length Normalization

The second adjustment BM25 makes is length normalization, which corrects a bias toward long documents. Without any correction, a long document naturally contains more occurrences of any term simply because it has more words, and it would win rankings unfairly. The parameter b, which ranges from 0 to 1, controls how aggressively the score is normalized by the ratio of the document length to the average length of the collection.

When b equals 1, full length normalization is applied and the term count is divided by the relative length of the document. When b equals 0, length is ignored entirely and the formula behaves as if every document were of average size. A value around 0.75 is the widely used default that balances the two extremes. The expression `1 - b + b * |D| / avgdl` in the denominator is precisely the knob that scales the saturation point according to how long the document is relative to its peers, so a long document must accumulate more matches before it earns the same score as a short one.

## Inverse Document Frequency in BM25

The `IDF(q_i)` factor rewards rare terms and discounts common ones, which is why a query word like "the" contributes almost nothing while a distinctive technical term dominates. BM25 uses a probabilistic variant of inverse document frequency:

```
IDF(q_i) = ln( (N - n(q_i) + 0.5) / (n(q_i) + 0.5) + 1 )
```

where `N` is the total number of documents and `n(q_i)` is the number of documents that contain the term. The `+ 1` inside the logarithm keeps the value non-negative even for terms that appear in more than half of the collection, a refinement over the classic Robertson-Sparck-Jones weight that could turn negative. This probabilistic weighting is what distinguishes BM25 from the simpler multiplicative scheme used in plain vector-space models.

## Practical Deployment

BM25 is implemented natively in Lucene, Elasticsearch, OpenSearch, and PostgreSQL full-text search extensions, and it powers the lexical arm of many hybrid pipelines. Because it operates on an inverted index, scoring is extremely cheap: the engine only touches documents that contain at least one query term, and posting lists are traversed in a single pass. This makes BM25 ideal as a recall-oriented first stage that narrows millions of documents down to a few hundred candidates.

A common pattern in retrieval-augmented generation is to run BM25 over a lexical index alongside a dense vector search, then merge the two ranked lists. BM25 excels at exact keyword matches, rare identifiers, product codes, and out-of-vocabulary tokens that embedding models handle poorly, so it complements semantic retrieval rather than competing with it. When people say a hybrid system "does keyword search", they almost always mean BM25 or a close variant under the hood.

Tuning advice tends to be empirical. Start with k1 around 1.2 and b around 0.75, then sweep both on a labelled query set while measuring recall and mean reciprocal rank. Corpora with highly variable document lengths, such as a mix of tweets and long articles, benefit from careful attention to b, whereas uniformly sized documents are relatively insensitive to it. Unlike neural rerankers, BM25 needs no GPU and produces deterministic, explainable scores, which is a considerable operational advantage.

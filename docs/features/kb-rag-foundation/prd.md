## 目标上线版本 v1.0

## 1. 背景与目标

### 1.1 背景
当前团队缺少可被 AI 高质量检索和引用的统一知识底座，导致一线人员检索效率低、答案一致性差、培训成本高。

### 1.2 v1.0 目标
在 0->1 阶段交付“可用版”能力：
- 文档统一接入并可增量更新
- 混合检索（关键词+向量）
- RAG 问答并强制来源引用
- 基础权限控制和审计
- 可执行的 RAG 评测基线

### 1.3 非目标（v1.0 不做）
- 跨系统 Agent 自动执行
- 知识图谱推理（GraphRAG）
- 复杂流程编排与自动工单闭环

## 2. 用户与场景

### 2.1 目标用户
- 客服与运营：快速定位标准答案
- 交付与实施：查找 SOP 与案例
- 管理者：检查回答来源与一致性

### 2.2 核心场景
- 场景 A：上传文档后可在 1 次索引内被检索命中。
- 场景 B：输入问题，3 秒内返回带引用答案。
- 场景 C：答案不确定时给出澄清建议与人工升级入口。

### 2.3 用户主流程（对象存储直传）
1. 用户在知识库页面选择文件并发起上传。
2. 系统返回预签名表单，浏览器直传到对象存储。
3. 上传完成后系统校验对象并生成上传台账记录（`uploaded_object`）。
4. 用户触发索引任务并查看任务状态。
5. 用户在检索/问答中验证新文档可被命中且带引用。

### 2.4 主流程成功判定
- 上传后在上传列表可见记录，状态为 `uploaded`。
- 索引任务状态为 `success`，且上传记录状态转为 `indexed`。
- 检索接口可返回对应文档的 `citation` 项。
- 问答接口返回 `grounded=true` 且包含至少 1 条引用。
- 无权限用户访问同一知识库时返回 `PERMISSION_DENIED`。

## 3. 需求范围

### 3.1 功能需求
1. 数据接入
- 支持对象存储（MinIO/S3）与 Wiki（首批两类）
- 支持定时增量同步

2. 上传资产管理
- 上传记录落库（`uploaded_object`）
- 支持列表/详情/软删除
- 支持上传状态追踪（`uploaded/indexed/failed/deleted`）

3. 数据处理
- 解析 PDF/Word/Markdown
- 清洗噪声（页眉页脚、重复段）
- 语义切片并保存版本信息

4. 检索与问答
- 混合检索（BM25 + 向量）
- 基础重排（规则或轻量模型）
- 生成带引用答案（文档+chunk）

5. 权限与审计
- RBAC（角色到文档范围）
- 查询与回答日志审计

6. 反馈与评测
- 用户反馈（有用/无用）
- 离线评测集跑分与版本对比

### 3.2 非功能需求
- 常规问答 TTFT < 3 秒（P95）
- 检索延迟 < 1.5 秒（P95）
- 核心可用性 >= 99.9%

---

## 4. 验收标准

### 4.1 功能验收
- 至少 2 类数据源可稳定增量同步
- 上传记录可查询、可软删除，且与对象存储状态一致
- 问答结果包含引用，且可跳转到原文位置
- 权限用户无法检索到越权文档
- 用户反馈可回流到评测报表

### 4.2 指标验收（首版门槛）
- Recall@10 >= 0.75
- 引用覆盖率 >= 95%
- 幻觉率 <= 8%
- 用户满意度 >= 70%

## 5. 里程碑与交付

- M1：上传、接入、清洗、切片、索引
- M2：检索、问答、引用
- M3：权限、审计、评测、灰度

每个里程碑交付：
- 功能清单
- 指标结果
- 回滚方案

---

## 6. 风险与应对

- 风险：文档质量低导致检索不稳定
  - 应对：建立高价值语料白名单与数据清洗规则
- 风险：模型生成漂移
  - 应对：强制引用 + 低置信兜底
- 风险：索引构建耗时超预期
  - 应对：异步队列 + 增量更新 + 分批发布

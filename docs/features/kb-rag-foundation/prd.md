## 目标上线版本 v1.0

## 1. 背景与目标

### 1.1 背景
当前团队缺少可被 AI 高质量检索和引用的统一知识底座，导致一线人员检索效率低、答案一致性差、培训成本高。

### 1.2 v1.0 目标
在 0->1 阶段交付“可用版”能力：
- 文档统一接入并可增量更新
- 混合检索（关键词+向量）
- RAG 问答并强制来源引用
- 基础权限控制和审计
- 可执行的 RAG 评测基线

### 1.3 非目标（v1.0 不做）
- 跨系统 Agent 自动执行
- 知识图谱推理（GraphRAG）
- 复杂流程编排与自动工单闭环

---

## 2. 用户与场景

### 2.1 目标用户
- 客服与运营：快速定位标准答案
- 交付与实施：查找 SOP 与案例
- 管理者：检查回答来源与一致性

### 2.2 核心场景
- 场景 A：输入问题，3 秒内返回带引用答案
- 场景 B：按部门/时间过滤后检索文档与段落
- 场景 C：答案不确定时给出澄清建议与人工升级入口

---

## 3. 需求范围

### 3.1 功能需求
1. 数据接入
- 支持本地文件夹、Wiki（首批两类）
- 支持定时增量同步

2. 数据处理
- 解析 PDF/Word/Markdown
- 清洗噪声（页眉页脚、重复段）
- 语义切片并保存版本信息

3. 检索与问答
- 混合检索（BM25 + 向量）
- 基础重排（规则或轻量模型）
- 生成带引用答案（文档+chunk）

4. 权限与审计
- RBAC（角色到文档范围）
- 查询与回答日志审计

5. 反馈与评测
- 用户反馈（有用/无用）
- 离线评测集跑分与版本对比

### 3.2 非功能需求
- 常规问答 TTFT < 3 秒（P95）
- 检索延迟 < 1.5 秒（P95）
- 核心可用性 >= 99.9%

---

## 4. 验收标准

### 4.1 功能验收
- 至少 2 类数据源可稳定增量同步
- 问答结果包含引用，且可跳转到原文位置
- 权限用户无法检索到越权文档
- 用户反馈可回流到评测报表

### 4.2 指标验收（首版门槛）
- Recall@10 >= 0.75
- 引用覆盖率 >= 95%
- 幻觉率 <= 8%
- 用户满意度 >= 70%

---

## 5. 里程碑与交付

- M1：接入、清洗、切片、索引
- M2：检索、问答、引用
- M3：权限、审计、评测、灰度

每个里程碑交付：
- 功能清单
- 指标结果
- 回滚方案

---

## 6. 风险与应对

- 风险：文档质量低导致检索不稳定
  - 应对：建立高价值语料白名单与数据清洗规则
- 风险：模型生成漂移
  - 应对：强制引用 + 低置信兜底
- 风险：索引构建耗时超预期
  - 应对：异步队列 + 增量更新 + 分批发布
